1. 简介

Soul Agent Launcher（SAL）是一个 Windows 桌面应用，用于启动、管理和监控 llama.cpp 推理服务。图形化界面替代命令行，支持 GPU 后端自动检测、模型下载、流式对话、会话管理与全局搜索。

特性说明
GPU 自动检测自动识别 NVIDIA（CUDA）、AMD/Intel（Vulkan）、CPU 后端
一键启动服务点按钮运行 llama-server，无需命令行
多模型管理同时运行多个模型，每个独立端口
智能待机 NEW平时零进程零显存，请求命中自动唤醒（/chat 与 OpenAI 双端点）
崩溃自动恢复 NEW进程意外退出自动重启（最多 3 次）
流式对话内置 SA Lite 聊天，支持深度思考显示与多模态
会话管理与全局搜索 NEW保存/加载聊天历史，跨会话全文搜索，长对话自动总结
应用内更新 NEW下载 → SHA256 校验 → 静默安装 → 自动重启
环境修复 NEWPython/pip/ModelScope/加速端 一键检测重装
开机自启 NEW托盘模式后台启动，自动恢复上次运行的模型
多语言中文/英文自动切换

技术栈

  • 前端框架：Tauri v2（Rust + WebView）
  • 推理引擎：llama.cpp（CUDA / Vulkan / CPU）
  • 本地存储：JSON 文件（会话、配置、模型列表）
  • 更新服务：独立 Flask 服务器（sal.bszx.site）

2. 安装与卸载

系统要求

  • Windows 10 / 11（64 位），x86_64 CPU（AVX2+），建议内存 16GB+
  • GPU（可选）：NVIDIA 驱动 ≥ 525（推荐 ≥ 570）；AMD/Intel 走 Vulkan
  • 磁盘：离线完整版约 460MB，在线版约 15MB

安装 / 卸载

双击 MSI 按向导安装（默认 C:\Program Files\Soul Agent Launcher\）。卸载走系统设置 → 应用。卸载不影响用户数据（位于 %APPDATA%\Soul-Agent-Launcher\）。

安装包类型大小说明
离线完整版 MSI~460MB内置全部 GPU 后端，无网络可用
在线轻量版 MSI~15MB需联网下载或预置 llama.cpp 包

3. 首次启动与自动配置

启动流程：启动 → 检测硬件 → 匹配后端包 → 解压 → 生成配置 → 就绪（十步自动化，每步失败可跳过或重试）。

硬件自动检测

  • NVIDIA CUDA：驱动 ≥ 570 → CUDA 13.3；≥ 525 → CUDA 12.4
  • Vulkan：AMD / Intel 等
  • CPU 兜底：无 GPU 时自动选用

内置后端（离线完整版）

包名大小适用
cuda-13.3151MBRTX 40xx Super / 50xx
cuda-12.4254MBGTX/RTX（较老）
vulkan-x6433MBAMD / Intel 独显
cpu-x6416MB任何 x86 处理器

Python / ModelScope

下载模型需要 Python + modelscope。缺失时 SAL 会静默安装（弹出 UAC 授权）。也可以随时在 设置 → 环境修复 里一键检测/重装。

4. 界面概览

左侧边栏导航：🏠 首页 · 📦 模型 · 🚀 启动 · 💬 会话 · 💭 对话 · 📚 知识库 · ⚙️ 设置；底部显示版本号。窗口关闭默认最小化到托盘（托盘菜单可退出/查看日志）。

5. 首页 —— 服务总控

首页显示服务状态灯（🟢 运行中 / 🟠 加载中 / ⚫ 未启动）、启停按钮、一键部署卡与 AI 跑分卡。状态每 5 秒自动刷新；模型加载中（503）会显示「模型正在加载中~马上就好~」。

6. 模型管理

「模型」页三个标签：本地模型 / 魔塔社区 / 官方模型。支持所有 GGUF 格式模型，可从魔塔搜索下载或手动放入 %APPDATA%\Soul-Agent-Launcher\models\。

加载模型时若估算显存需求超出当前可用显存，会弹出预警，可选择继续或取消。

7. 启动页 —— 高级控制与智能待机

服务参数

参数默认值说明
端口20000主服务端口
上下文4096推理上下文长度
连接数8最大并发连接

智能待机 NEW

「已启动模型」列表中每个模型可点「待机」/「唤醒」：

待机 → llama 进程完全停止（显存/内存零占用）
请求 → 命中待机模型的请求自动唤醒（/chat 与 /v1/chat/completions 双端点）
就绪 → /health 通过后自动转发，客户端无感
  • 空闲自动待机：设置 → 默认参数 → 空闲自动待机（关闭/5/10/30 分钟），空闲超时自动释放显存（正在生成的请求不会被打断）
  • 预唤醒：聊天页点击输入框即预唤醒当前待机模型，打字时模型已在加载
  • 多模态：设置中配置 mmproj 路径后，多模态模型待机唤醒后视觉能力原样保留

崩溃自动恢复 NEW

后台监控线程每 5 秒巡检，llama 进程意外退出时按原参数自动重启（最多 3 次），控制台与托盘提示。自动待机/崩溃恢复在托盘后台运行时同样生效。

手动编译（高级）

设置 → 极致精简编译：选择 build-minimal.ps1 后一键编译 CPU-only 精简版 llama-server（需 CMake + MSVC）。

8. SA Lite —— 极简对话

  • Enter 发送 / Shift+Enter 换行；支持流式输出与打字动画
  • 深度思考块（可折叠）；多模态模型可发图片
  • 上下文环形指示器：80% 静默自动总结、95% 强制总结，总结注入后续请求
  • 模型快切下拉：切换到待机中的模型时，聚焦输入框即自动预唤醒

9. 会话管理与全局搜索

「会话」页管理历史会话（新建/重命名/删除）。数据存储于 %APPDATA%\Soul-Agent-Launcher\sessions\。

全局搜索 NEW

会话页顶部搜索框可跨全部会话搜索消息内容（不区分大小写），命中结果显示会话标题、角色与上下文片段，点击直接跳转到对应会话。

10. 设置与环境修复

通用设置

llama.cpp 路径、模型目录、默认端口（20000）、默认上下文（4096）、语言、主题。

行为 NEW

  • 退出时自动卸载模型：关闭窗口后清理所有模型进程
  • 开机自启动（托盘模式）：系统启动后台运行，设置立即生效
  • 启动时自动恢复上次运行的模型：下次启动自动重新加载

环境修复 NEW

Python / pip / ModelScope / llama.cpp 加速端四个组件的状态灯与一键重装。打开设置页自动体检一次；组件异常点「一键修复」（可能弹出权限窗口）。加速端修复按当前硬件自动匹配。

mmproj（多模态）

设置 → 默认参数 → mmproj 路径：多模态模型启动时自动附加 --mmproj，待机唤醒后原样恢复。注意：此路径会附加到所有启动的模型，混用纯文本模型时请勿填写。

11. 自动更新

检查机制

  • 自动检查：启动后 3 秒（服务器 sal.bszx.site）
  • 手动检查：设置 → 检查更新

应用内更新 NEW

下载（按钮内嵌进度条）→ SHA256 完整性校验 → UAC 授权
→ 关闭旧版 → 静默安装 → 自动启动新版

校验失败（安装包损坏）会拒绝安装并提示重新下载；取消 UAC 授权则不会安装，可稍后重试。

管理后台

https://sal.bszx.site/admin：登录后填写版本号与说明、上传 MSI（自动计算 SHA256）、选择是否强制更新、发布。

12. 多语言支持

简体中文 / English。系统语言自动切换，也可在设置中手动选择（保存到本地）。切换即时生效于导航、状态、会话列表与输入框等界面文案。

13. 常见问题

Q：一直显示「未启动」？

首次安装需自动解压后端包，稍等几秒；端口被占用时更改默认端口；后端包不完整时重新安装完整版 MSI。

Q：模型加载报错？

OOM → 降低上下文或换小模型；文件损坏 → 重新下载；格式必须为 GGUF。显存预警弹出时说明可用显存不足。

Q：503 "Loading model"？

正常现象，模型正在加载显存，10-30 秒后自动变为运行中。

Q：模型待机后显存真的释放了吗？

是。待机完全停止该模型的 llama 进程，显存立即归零，仅保留代理端口。下一次请求（/chat 或 OpenAI 端点）自动唤醒并等待加载完成，无需手动操作。

Q：为什么待机后再次请求要等一会儿？

待机状态下模型不在显存，请求命中时自动重新加载（数秒~数十秒）。技巧：聊天页点击输入框即开始预唤醒，打字时模型已在加载。

Q：按钮点了没反应？

关闭重开应用；反复出现则重装 MSI；检查日志 %APPDATA%\SoulLogs\（托盘菜单「查看日志」直达）。

Q：聊天记录不见了？

检查 %APPDATA%\Soul-Agent-Launcher\sessions\，文件存在则重启应用自动加载。

Q：如何手动添加模型？

GGUF 文件放入 %APPDATA%\Soul-Agent-Launcher\models\，模型页点刷新。

Q：更新后配置会丢失吗？

不会。用户数据在 %APPDATA%\Soul-Agent-Launcher\，与安装目录分离。

Q：日志在哪里？

%APPDATA%\SoulLogs\soul_YYYY-MM-DD.log，托盘菜单「查看日志」直达。
